## Прогноз

* `healthy` - приложение создает запись в базе данных, делает одну синхронную попытку отправить уведомление и возвращает `201 Created`. Задание на повторную попытку не сохраняется.
* `slow` - аналогично `healthy`, но провайдер ждет 2 секунды перед тем, как отправить подтверждение. Ожидается, что запрос будет выполняться дольше по времени примерно на 2 секунды.
* `unavailable` - провайдер уведомлений недоступен, уведомление не отправляется повторно после его восстановления. Приложение все равно возвращает `201 Created`, работа утеряна (отправка уведомления не состоялась).

## Условия опыта

* API такси в режиме `direct`;
* Режимы провайдера: `slow` (задерживает обработку запроса на 2 секунды) и `unavailable` (сразу возвращает ошибку `503`).

## Вывод

API такси во всех случаях возвращает успех: `201 Created`.
Исходный договор не отвечает требованиям, так как теряется работа по доставке в случае, если провайдер недоступен.

В таблице `provider_deliveries` только запись из опыта `slow`, для поездки из прогона `unavailable` в `provider_deliveries` нет записи о доставке.
